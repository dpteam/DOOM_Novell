# Архитектура

Проект состоит из двух независимых половин:

1. **Конвейер ассетов** (`tools/`, Python + Pillow + numpy) — читает IWAD и
   собирает `game/`.
2. **Игра** (`game/`, Ren'Py 8.5) — обычная визуальная новелла, которая просто
   использует результат конвейера.

Их связывает только файловая система и `game/fonts/fonts.json` (список
зарегистрированных bitmap-шрифтов).

## Конвейер

```
tools/
  build_assets.py      точка входа: --iwad, --out, --skip-music, --ttf
  wadinfo.py           быстрый просмотр содержимого WAD
  gen_images_rpy.py    генерирует game/images.rpy по факту собранных файлов
  preview.py           отладочная отрисовка пары сцен
  font_preview.py      проверка сгенерированных шрифтов
  scratch.py           песочница для подбора текстур (не нужна для сборки)
  wadlib/
    wadfile.py         чтение WAD: lumps, PLAYPAL, COLORMAP, патчи, TEXTURE1, флэты, спрайты
    audio.py           DMX → WAV, MUS/MIDI → события, синтез трека, WAV
    mapdata.py         геометрия уровней и отрисовка планов этажей
    art.py             композит сцен, панели интерфейса, постер, виньетка, зерно
    fonts.py           сборка BMFont из патчей и из TTF
```

Ключевые решения:

- **Никакого внешнего софта, кроме опционального `ffmpeg`.** Всё остальное —
  Pillow и numpy. Это значит, что пересборка воспроизводима на любой машине.
- **Детерминированность.** Все случайности (зерно, кровь, выбор кадра) засеяны
  от ключа сцены, поэтому повторная сборка даёт байт-в-байт те же картинки.
- **Совместимость с FreeDoom.** Пайплайн не полагается на конкретные имена
  (кроме стандартных для DOOM), а отсутствующие lump'ы пропускает с
  предупреждением, поэтому `freedoom2.wad` собирается тем же скриптом.
- **Совместимость DOOM1.** Если в WAD нет `MAP01..MAP32`, конвейер берёт
  `E1M1..E4M9`.

## Игра

```
game/
  script.rpy            старт, карточки глав, переходы между главами
  story/
    ch1_hr.rpy          приёмная, эйчар Алексей
    ch2_office.rpy      второй этаж, принтер, Борис
    ch3_hell.rpy        адский опенспейс, барон и коуч
    ch4_canteen.rpy     столовая и серверная
    ch5_throne.rpy      тронный зал и все концовки
  characters.rpy        Character-объекты, состояние игрока, хелперы (фраги, урон)
  images.rpy            объявления изображений (генерируется)
  fonts.rpy             регистрация bitmap-шрифтов из fonts.json
  theme.rpy             стили: цвета, шрифты, панели, трансформы
  screens.rpy           база Ren'Py GUI (перекрашена под проект)
  screens_custom.rpy    HUD, карточки глав, архив, бестиарий, сводка забега
  testcases.rpy         smoke-тест: меню → вся игра → титры → меню
  _shots.rpy            харнесс скриншотов (DOOM_NOVELL_SHOTS=1)
  gui.rpy               переменные GUI (цвета, размеры, шрифты)
  options.rpy           конфигурация, музыка, упаковка
  guisupport.rpy        заглушка gui.scale() из шаблона
```

### Порядок инициализации

Важная часть, потому что шрифты — bitmap:

| Приоритет | Файл | Что делает |
| --- | --- | --- |
| `-100` | `fonts.rpy` | читает `fonts/fonts.json`, кладёт в `FONT` |
| `-2` | `gui.rpy` | `gui.init(1280, 720)` и все переменные GUI |
| `-1` | `screens.rpy` | стили шаблона Ren'Py |
| `0` | `fonts.rpy` | `renpy.register_bmfont()` для 4 вариантов начертания |
| `5` | `theme.rpy` | финальные переопределения стилей |

`theme.rpy` специально стоит на `init offset = 5`: он должен победить стили
шаблона, иначе наш текстбокс и кнопки оказались бы стандартными.

`game/testcases.rpy` — отдельный слой: тесты в 8.5 живут в своём DSL
(`click`, `advance`, `pause`, `screenshot`, `testsuite`/`testcase`) и
запускаются командой `renpy . test smoke`.

Пара (шрифт, размер) в стилях должна совпадать с `fonts/fonts.json`:
bitmap-шрифт нельзя отрисовать «другим кеглем». Шрифты регистрируются под
путём файла (`fonts/cyr26.fnt`) во всех четырёх начертаниях — так и ошибок
меньше, и `lint` не жалуется на «not loadable».

**Следствие:** `{size=N}` внутри текста и `size N` внутри стиля — запрещены,
если для этой пары нет отдельного `.fnt`. Ren'Py 8.5 в таком случае падает с
`FreetypeError: unknown file format`, а не подставляет что-то похожее. Для
разных кеглей одного и того же текста делайте разные стили — см.
`card_title` / `card_sub` / `card_body` в `theme.rpy` и `characters.rpy`.

Атлас глифов хранит маску в RGB **и** в альфе: Ren'Py красит image-шрифты
через `linmap` (красный канал) и напрямую через blit (альфа).

### Состояние

Всё в `store` (см. `characters.rpy`):

| Переменная | Смысл |
| --- | --- |
| `hp`, `armor`, `ammo` | HUD и проверки в финале |
| `kills` | сколько раз сержант нажал на курок |
| `mercy` | сколько раз договорился |
| `promises` | сколько раз пообещал что-то корпорации |
| `has_chainsaw` | открывает секретную концовку |
| `persistent.endings` | разблокированные концовки (для архива) |
| `persistent.seen_bestiary` | встреченные персонажи |

Хелперы: `add_kill()`, `add_mercy()`, `take_damage()`, `spend_ammo()`,
`remember()`, `unlock_ending()`, `mus()` (выбирает `.ogg` или `.wav`).

### Экраны

- `say` — стандартный, но в него добавлен `use hud`; поэтому HUD живёт ровно
  столько, сколько реплика, и не лезет в меню.
- `chapter_card(num, title, sub, mapname)` — карточка главы, вызывается через
  `call screen`, подложкой служит настоящий план этажа из WAD.
- `archive` — три вкладки: концовки, бестиарий, 32 плана уровней с просмотром.
- `run_summary` — итоги забега, показывается перед титрами.

### Трансформы

`stage_left`, `stage_right`, `stage_center` — позиции спрайтов; `ch_in`,
`ch_out` — вход/выход; `ch_breathe`, `ch_shake` — «дыхание» и тряска;
`white_flash` и `Fade` — вспышки.

## Как добавить сцену

1. Добавить запись в `SCENES` в `tools/build_assets.py` (стена, боковина, пол,
   потолок, дверь, акцент, декор).
2. `python tools/build_assets.py --iwad ... --out . --skip-music`
3. `python tools/gen_images_rpy.py`
4. В сценарии: `scene bg <ключ>`.

## Как добавить персонажа

1. Добавить запись в `CHARACTERS` (`sprite` — префикс спрайта, `height`).
2. Пересобрать ассеты и `images.rpy`.
3. `define кто = Character("ИМЯ", color="#...")` и `show <ключ> neutral at stage_left`.

## Почему всё сделано именно так

- **Одна сцена = одна текстура-коробка**, а не нарисованный фон: так работает
  масштабирование и не нужно рисовать 11 иллюстраций.
- **HUD внутри `say`**, а не отдельным overlay: меньше багов с меню и
  скриншотами сохранений.
- **Карточки глав из настоящих планов уровней**: бесплатный контент, который
  при этом выглядит как тактическая карта, а не как заглушка.
- **Пиксельные шрифты вместо TTF**: 1-битная растрированная кириллица даёт
  нужный ретро-вид и не требует тащить в репозиторий тяжёлый TTF.
